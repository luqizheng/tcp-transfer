## 新增 Dockerfile-linux（musl 静态构建）

**目标**：为 tcp-transfer 提供 Linux 版本构建，基础镜像使用内网私服 `zhcoder-docker-registry.com:8000/builder/rust:1.96-slim-musl`。

**产出文件**
- `Dockerfile-linux` — 两阶段构建：builder（rust:1.96-slim-musl，产出静态 musl 二进制）+ alpine:3.20 运行时（非 root 用户 uid 10001）
- `.dockerignore` — 排除 target/、dist/、.git/、Dockerfile* 等
- `.gitignore` — 补充 `/dist/`
- `dist/tcp-transfer` — 导出的 Linux 静态二进制（1,759,424 字节）

**关键坑与结论（重要，务必保留）**

1. **私服只支持明文 HTTP，不支持 TLS**。`https://zhcoder-docker-registry.com:8000` 返回 connection reset，`http://` 正常。
   - 该仓库是 Harbor，token 端点为 `/service/token`，`/v2/` 直连返回 401。
   - Docker 29 / BuildKit 对其执行 `docker login` 会报 `503 Service Unavailable`（Harbor 版本与 Docker 29 的 ping 不兼容），但**只要本地已有该镜像，用 `--pull=false` 构建即可绕过**，无需登录。

2. **构建时必须加 `--pull=false`**（本地已有基础镜像时），否则 Docker 会尝试联网访问私服并因 TLS 问题失败（`Head ...: EOF`）。

3. **`crt-static` 生效方式（核心坑）**：基础镜像的 `~/.cargo/config.toml` 里为 musl target 固定了 per-target 数组：
   ```toml
   [target.x86_64-unknown-linux-musl]
   linker = "clang"
   rustflags = ["-C", "link-arg=-fuse-ld=mold"]
   ```
   per-target 的 `rustflags` 数组会**完全替换** `RUSTFLAGS` 环境变量（而非合并），所以直接 `export RUSTFLAGS="-C target-feature=+crt-static"` **完全无效**。
   正确做法：用 `sed` 往原数组里**追加** `-C target-feature=+crt-static`，这样既保留镜像自带的 mold 链接器参数，又实现静态链接。

4. **musl 的 `ldd` 会误报**：对已静态链接的二进制，musl `ldd` 会打印 `/lib/ld-musl-x86_64.so.1 (...)` 看似是动态链接，这是**误报**（musl 工具链特性）。
   - 判定静态的正确方法：① `readelf -l` 无 `PT_INTERP` 段；② 放进 `FROM scratch` 镜像能正常运行。
   - 本二进制已验证在 scratch（零库、零 shell）中可正常运行 → **确认完全静态**，为 static PIE。

5. **Git Bash 路径转换坑**：Windows 下用 Git Bash 调 `docker cp` / `docker build` 时必须加 `MSYS_NO_PATHCONV=1`，否则 `/d/kudi-project/...` 会被改写成 `d:\d\kudi-project\...` 导致路径错误。

**验证结果**
- 镜像 `tcp-transfer:linux`：`--version` 输出 `tcp-transfer 0.1.0`，运行用户 `app` (uid 10001)
- scratch 容器中可执行 → 确认静态链接
- 端到端转发测试通过：后端 python http.server:80，转发器 listen 8080，客户端经转发器收到的响应与直连后端**完全一致**（`HTTP/1.0 200 OK`）

## CLI 二次简化：收敛为 -l / -t 两参数（用户要求）

**用户原话**：「参数你再简化。`--target` 和 `--port` 应该我是不需要的。用 `-l 0.0.0.0:444` 和 `-t 192.2.3.3:333` 就可以」

**用户确认的决策**：`-l`/`-t` 都必填且写完整 `host:port`；保留 `-v`/`--json-log`；**直接删掉** `-p`/`--target`/`--target-port`。

**最终 CLI**
```
tcp-transfer -l 0.0.0.0:444 -t 192.168.2.203:333
```

**改动文件**
- `src/cli.rs` — 重写。`listen` 改回字段名（类型 `SocketAddr`，clap 自动校验）；`target` 改 `String`；
  删除 `port` / `target_port` / `listen_addr()`；`target_addr()` 保留但简化为 `self.target.clone()`
- `src/main.rs` — 删掉 `listen_addr()` 调用和 0.0.0.0 提示行（用户现在自己写监听地址，无需提示）
- `Dockerfile-linux` — CMD 改为 `["-l","0.0.0.0:444","-t","127.0.0.1:80"]`
- `README.md` / `AGENTS.md` — 全量同步到新参数

**关键设计决策（写进 AGENTS.md §4，避免后人"统一"）**
- `listen: SocketAddr` —— 本机 IP 字面量，用 SocketAddr 可让 clap **启动前**就拒绝 `0.0.0.0`（漏端口）
- `target: String` —— **必须支持域名**（`example.com:80` 无法解析为 SocketAddr），不能改成 SocketAddr

**验证结果（全部通过）**
- `--help` 显示 `-l/--listen`、`-t/--target`，必填项正确
- 用户原用法 `-l 0.0.0.0:444 -t 192.2.3.3:333` → 日志 `listen=0.0.0.0:444 target=192.2.3.3:333` ✅
- `-l 0.0.0.0`（漏端口）→ clap 报 `invalid socket address syntax` ✅
- `-l 0.0.0.0:99999`（端口越界）→ 同样被拒 ✅
- `-t example.com:80`（域名）→ 正常接受 ✅
- 旧参数 `-p` → `error: unexpected argument '-p' found` ✅
- 端到端：`-l 0.0.0.0:444 -t backend:333`，经转发器响应与直连一致 ✅
- 镜像默认 CMD 生效，`--help` 正常 ✅

**副产品收益**：三段式时代那个「`--target X:2000` 拼出畸形地址 `X:2000:100`」的缺陷
**自然消失**了——不再有端口拼接逻辑。AGENTS.md §10 已把该待办标记为「已解决」。
